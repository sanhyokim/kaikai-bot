# 決めたことと理由(実装役)

仕様書に書いていないことで、実装役が「シンプルで確実」な方を選んだ記録です。仕様書と食い違うものは無く、食い違いそうな点は最後の「提案・確認待ち」に分けています。

## 段階1

### 指標の細かい決まりは広く使われる計算ライブラリ(TA-Lib)に合わせた
仕様書は「標準の計算」としか書いていない部分があるため、試験の照合相手と同じ決まりにした。本体は TA-Lib を使わず自前で計算し、試験の既知の値だけ TA-Lib で作った(tests/make_known_values.py)。
- 指数移動平均の最初の値は、先頭 n 本の単純平均。
- ATR の真の値幅は前の終値が要るので2本目から。最初の ATR は2本目〜15本目の単純平均。
- パラボリックの始まりの向きは、2本目の高値・安値の動きで決める。足が SAR に触れたら(等号でも)反転する。反転した足の SAR は、その足と1本前の足の値幅の外側に置く。

### 収集は確定した足だけ保存する
取得の入口は作りかけの足も返すが、検証で使うのは閉じた足だけなので、保存しない。後から確定値で上書きする仕組み(仕様書 5.2)はそのまま。

### 初回の収集は取れるだけ取る
保存庫が空の時は「最新の1時間前」が無いので、取得できる最も古い足から取る。

### 米国株3銘柄も今日から収集する
仕様書では収集の追加は段階5だが、過去は約3.6日分しか取れず、待つとその分のデータが永久に失われる。収集だけなら取引に影響しないので、最初から設定ファイルの全6銘柄を集める。判定表への追加は仕様書どおり段階5で行う。

### 設定の読み込み用に小さなファイルを1つ足した
`kaikai_bot/config.py`。設定ファイルとデータの置き場所を1か所で読むためだけのもので、売買判断は書かない。

### 収集の状態と警告の置き場所
状態(銘柄ごとの最終取得時刻・連続失敗回数)は `logs/collect_status.json`、警告は `logs/alerts.log`。監視画面はこの2つを読む。

### 除外日の判定は UTC の1日 1440本を基準にする
データの最初の日・最後の日のように途中から始まる日も、1440本の95%に届かなければ除外する。検証に使う日はすべて丸1日そろった日になる。

### 指標は欠損をまたいで計算する
欠損のたびに計算し直すと、毎回長い計算不能期間(長い移動平均は75本+10本)ができる。仕様書 5.4 の「欠損明け10本は入らない」「欠損の直前で手仕舞い」で取引は欠損をまたがないので、指標は残った足を順につないで計算する。

### 米国の休日表は 2026年・2027年
NYSE 公式の休日表から転記。過去データを補う場合は、その年を足す。13時の短縮取引日は仕様書に扱いが無いので記録だけして使っていない。

## ボスが決めた仕様書からの変更(Commander に版上げを依頼する)

### 収集は GitHub の自動実行で1時間ごとに動かす(2026-10-25 ボス決定)
- 仕様書 5.5 は「cron か Windows タスクスケジューラ」。ボスのパソコンが3日以上止まるとデータが永久に欠けるため、GitHub の自動実行(`.github/workflows/collect.yml`)で動かす。
- 貯め方: リポジトリの `data` 枝に `candles/<銘柄>/<UTC日付>.csv`。銘柄名の「:」は「_」に置き換え(xyz:NVDA → xyz_NVDA)。欠損の記録 `gaps.log` と状態 `collect_status.json` も同じ枝に置く。
- パソコンでは `python -m kaikai_bot.collect --from-github` で `data/market.db` に取り込む。保存の形(5.2 の表)は変えていない。
- 版上げの文案(5.5 の1行目の差し替え): 「`python -m kaikai_bot.collect --store <保管庫>` を GitHub の自動実行で1時間に1回動かし、data 枝に日ごとのファイルで貯める。パソコンでは `--from-github` で取り込む。」

### 過去データの保管庫(公式の約定記録)は今は使わない(2026-10-25 ボス決定)
AWS 契約が要るため見送り。判定は毎日の収集で約225日分が貯まってから。
